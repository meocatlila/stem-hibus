# แผนออกแบบและพัฒนาตัวรถต้นแบบไฮบัส (KidBright)

เอกสารนี้สรุปจากผลการสัมภาษณ์ออกแบบ + [HIBUS_VEHICLE_RESEARCH.md](./HIBUS_VEHICLE_RESEARCH.md) + [HIBUS_VEHICLE_DECISIONS.md](./HIBUS_VEHICLE_DECISIONS.md)

ขอบเขตวันสาธิต: รถพิสูจน์ **ตามเส้น + หยุดที่ป้าย + ตัวถังยกสูง**  
แอปนำทางเป็นคนละชิ้น — ไม่เชื่อมข้อมูลกับบอร์ด

---

## 1. ข้อสรุปการออกแบบที่ล็อกแล้ว

| หัวข้อ | การตัดสินใจ |
| --- | --- |
| จุดขายบนเวที | ตามเส้น + หยุดป้าย และตัวถังยกสูง เห็นชัดทั้งคู่ |
| เครื่องหมายป้าย | เทปดำ (เช่น เทปพันสายไฟ) คาดขวางบนเทปเส้นทาง |
| พฤติกรรมหยุด | หยุดนิ่งจนกว่าจะกดปุ่มบน KidBright แล้วไปต่อ |
| ตัวถัง | ฐานชุดตามเส้น + โฟมบอร์ด/กระดาษแข็งยกสูง |
| สนาม | สายเดียว (วงรี/เส้นปิด) มีป้าย 2–3 จุด |

---

## 2. สถาปัตยกรรมชิ้นงาน

```
ชั้นบน: ตัวถังโฟมบอร์ดรูปรถเมล์ (เบา, ศูนย์ถ่วงไม่สูงเกิน)
   │ เสารอง / สเปเซอร์ → ช่องลอดใต้ท้องให้รถเตี้ยจำลองผ่านได้
ชั้นล่าง: ฐาน KB Robot / ล้อ + มอเตอร์ + IR หันลงพื้น
   │ สาย KB Chain
KidBright32: อ่าน IR + ปุ่ม → สั่งมอเตอร์ผ่านไดรเวอร์
สนาม: พื้นสว่าง + เทปดำเป็นเส้นทาง + เทปคาดขวาง = ป้าย
```

## 4. รูปแบบสนามที่แนะนำ

- รูปวงรีหรือสี่เหลี่ยมมุมโค้ง บนโต๊ะสาธิต
- เส้นทางเทปดำความกว้างสม่ำเสมอ
- ป้าย 2 หรือ 3 จุด: วางแถบคาดขวางให้ทั้งเซนเซอร์ซ้ายและขวาเหยียบดำพร้อมกัน
- จุดหนึ่งเว้นที่ว่างข้างเส้นให้โชว์รถเตี้ยลอดใต้ตัวถัง
- ไม่ทำทางแยกในรอบแรก — ลดโอกาสสับสนระหว่าง “ทางแยก” กับ “ป้าย”

## 5. อัลกอริทึมโปรแกรม (KidBright IDE — แนวบล็อก)

สถานะหลัก: `FOLLOW` → `STOP_WAIT` → `LEAVE_MARK` → กลับ `FOLLOW`

```
เมื่อเริ่มต้น:
  ตั้ง state = "FOLLOW"
  หยุดมอเตอร์
  (ทางเลือก) รอ กด Switch1 ครั้งแรกเพื่อออกตัว

วนซ้ำตลอด:
  อ่าน L, R จากเซนเซอร์ IR

  ถ้า state = "FOLLOW":
    ถ้า L เป็นดำ และ R เป็นดำ:          // เจอเทปคาด = ป้าย
      หยุดมอเตอร์ทั้งสอง
      (ทางเลือก) แสดง "STOP" บนจอ / มีเสียงสั้น
      ตั้ง state = "STOP_WAIT"

    ไม่เช่นนั้นถ้า L ขาว และ R ขาว:
      วิ่งตรง ความเร็ว V

    ไม่เช่นนั้นถ้า L ดำ และ R ขาว:
      เลี้ยวซ้าย / ลดความเร็วล้อซ้าย

    ไม่เช่นนั้นถ้า L ขาว และ R ดำ:
      เลี้ยวขวา / ลดความเร็วล้อขวา

  ถ้า state = "STOP_WAIT":
    มอเตอร์หยุด
    ถ้า กดปุ่ม (เช่น Switch2):
      ตั้ง state = "LEAVE_MARK"

  ถ้า state = "LEAVE_MARK":
    วิ่งตรงช้า ๆ ความเร็ว V_slow
    จน L หรือ R กลับเป็นขาว (พ้นแถบคาด)
      หรือ หน่วงเวลาสั้น t_clear เป็นตัวช่วย
    ตั้ง state = "FOLLOW"
```

### จุดสำคัญที่ต้องทำในโปรแกรม

1. **แยกปุ่มออกตัวกับปุ่มไปต่อ** (แนะนำ: Switch1 เริ่มงาน, Switch2 ออกจากป้าย) เพื่อไม่กดผิดจังหวะ
2. **ต้องมี LEAVE_MARK** หลังกดปุ่ม ไม่งั้นรถจะอ่านแถบคาดซ้ำแล้วหยุดทับที่เดิม
3. คาลิเบรตค่าดำ/ขาวบนสนามจริงวันซ้อม — แสงห้องเปลี่ยนค่าได้
4. ความเร็วเข้าป้ายไม่สูงเกินไป เพื่อไม่ข้ามแถบคาด

---

## 6. ลำดับงานสร้าง (แนะนำ)

1. ประกอบฐานขับเคลื่อน + IR ให้ตามเส้นบนสนามทดลองได้ก่อน (ยังไม่ติดตัวถัง)
2. วาดเส้นทาง + วางแถบคาด 1 จุด ทดสอบเงื่อนไขหยุด
3. ใส่สถานะรอปุ่ม + LEAVE_MARK ทดสอบ 2–3 ป้ายรอบวง
4. ติดเสารองและตัวถังโฟมบอร์ด ตรวจว่าไม่บัง IR และไม่คว่ำตอนเลี้ยว
5. ซ้อมบทสาธิต: รถวิ่ง → หยุดป้าย → อธิบาย → กดปุ่ม → ไปป้ายถัดไป → โชว์รถเตี้ยลอดใต้ท้อง
6. เตรียมประโยคตอบกรรมการ: แอปกับรถแยกกัน; ป้ายเป็นกติกาที่ทีมออกแบบเอง ไม่ใช่ฟีเจอร์สำเร็จรูปของชุด

## 7. เกณฑ์สำเร็จวันสาธิต

- [ ] รถอยู่บนเส้นได้รอบวงโดยไม่หลุดบ่อย
- [ ] ทุกจุดคาดขวางสั่งหยุดได้
- [ ] กดปุ่มบนบอร์ดแล้วรถไปต่อป้ายถัดไปได้
- [ ] เห็นช่องว่างใต้ท้อง และมีรถเตี้ยลอดผ่านได้ตอนสาธิต
- [ ] ทีมอธิบายได้ว่าป้าย = เทปคาด + โปรแกรมตรวจ IR ทั้งสองตัว

## 8. ความเสี่ยงและการแก้

| ความเสี่ยง | การแก้ |
| --- | --- |
| หยุดกลางเส้นเพราะเส้นหนา/คราบ | เส้นทางบางสม่ำเสมอ; แถบป้ายหนาเฉพาะจุดคาด |
| ไม่หยุดที่ป้าย | ทำแถบคาดกว้างขึ้น; ลดความเร็ว |
| กดปุ่มแล้วยังติดป้ายเดิม | บังคับ LEAVE_MARK ก่อนกลับ FOLLOW |
| ตัวถังพลิก | ลดความสูง/น้ำหนักชั้นบน; ลดความเร็วเลี้ยว |
| มอเตอร์ทำให้บอร์ดรีเซ็ต | แยกไฟมอเตอร์จากไฟควบคุม |
| กรรมการคิดว่าแอปสั่งรถ | ย้ำตั้งแต่ต้นว่าสองระบบอิสระ |

## 9. สิ่งที่ยังปรับละเอียดได้ตอนลงมือ

- จำนวนป้ายบนวง: 2 หรือ 3
- ปุ่มไหนใช้ “ไปต่อ” (Switch1 / Switch2)
- ความสูงช่องลอดให้พอดีรถของเล่นที่มีจริง
- จะแสดงคำว่า STOP บนจอ LED ตอนจอดหรือไม่
